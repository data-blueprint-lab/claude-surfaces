Copilot or Claude Code

00The short answer

Three things dissolve most of this question before the comparison starts.

"Copilot" is at least three products, and only one is comparable to Claude Code. GitHub Copilot is a coding assistant in your editor. Copilot in Fabric is Fabric's own AI, different in each workload, billed to your Fabric capacity. The Microsoft 365, Studio and Azure Copilots are something else again. A comparison that doesn't say which is comparing nothing.

It is a false choice at the model layer. Claude models are available inside GitHub Copilot — Haiku, Sonnet and Opus across several versions, plus the Fable frontier models. The Fabric-specific agent runs on Claude Sonnet 4.5, Claude Opus 4.6, or GPT-5.2. You can already be using Claude through Copilot. What you actually choose is the harness: where the agent sits, what it reaches, and who gets billed.

Yes, Copilot reaches Fabric from VS Code — and for notebooks it is ahead. The Fabric Data Engineering extension browses lakehouses, runs notebooks on remote Spark, and edits workspace items in place. On top of it sits a Fabric-aware agent inside Copilot Chat that knows the spark session variable and Fabric's lakehouse path conventions. Claude Code has no Fabric awareness at all; it reaches Fabric through the Model Context Protocol (MCP) or the fab CLI, as the companion page describes.

The recommendation in four sentences

Run both, with roles: Copilot in the editor for notebook authoring, where its Fabric integration is a real advantage, and Claude Code in the terminal for anything scripted, cross-repo or CLI-driven. The hard decision is neither of those — it is whether to enable Copilot in Fabric, which spends your data platform's compute budget and can throttle your own pipelines. Decide that one on cross-geo data processing and capacity isolation, not on output quality. And if you enable it, isolate its capacity first.

02Same job, different chair

GitHub Copilot's agent mode and Claude Code have converged much more than the marketing suggests. Both read a codebase, edit across many files, run terminal commands, react to test failures in a loop, and speak the Model Context Protocol.

In plain terms

Think of it as where you sit. Claude Code sits in the terminal, so it is good at things that look like commands and pipelines. Copilot sits in the editor, so it is good at things that look like the file you are already staring at. Both can now do the other's job — just less well.

03Reaching Fabric from VS Code

This is the part that surprised me, and it is a genuine point for Copilot.

What the extension gives you

  • Workspaces — manage one or several from the editor
  • Lakehouses — browse tables and files, preview data, copy paths for your code
  • Notebooks — create, edit and run, locally or on remote Spark compute
  • Spark job definitions — full create, read, update, delete
  • Environments — inspect hardware profiles, libraries, Spark configuration
For the implementer — modes, kernels and containers

Local mode downloads items, you edit locally and sync back. VFS mode is a virtual file system: edit remote Fabric items with no download, several workspaces in one window, changes syncing on save. Open it from the Fabric portal via "Open In VS Code (Desktop)".

For runtime 1.3 and higher no local conda environment is created — you pick a Microsoft Fabric Runtime kernel and the notebook executes on remote Spark. That is the right choice when your code has hard remote dependencies; MSSparkUtils and NotebookUtils only exist there. Local conda still earns its keep for working disconnected, or testing a library before you upload it. Microsoft also publishes a dev-container image on its Artifact Registry with JDK, Conda and Jupyter preinstalled, if you would rather none of this touched your machine.

Note what this implies

The Fabric-native agent in Microsoft's own tooling runs on Claude models. If you were choosing between "Copilot" and "Claude" as rival brains, the premise does not survive contact with the documentation. The competition is between harnesses, not models.

04Three cost models, and a trap

GitHub CopilotBusiness $19/user (1,900 AI credits), Enterprise $39/user (3,900). Credits pool at enterprise level; overage $0.01/credit. Completions unbilled and unlimitedSoftware subscription

Three observations that change decisions:

  • Claude's pool is per person; Copilot's is pooled across the organisation. Opposite designs with opposite failure modes. With Claude a heavy user cannot drain a colleague; with Copilot they can, but light users subsidise heavy ones. For a team of a dozen, pooling is usually the better deal, and it removes the per-person upgrade decision entirely.
  • Completions are free on Copilot, and that is not small. The unlimited, unbilled part is the part developers touch most. Credits only start moving in chat and agent mode.
  • Copilot in Fabric competes with your production workloads. Microsoft is explicit that overconsumption "can lead to throttling and disruption of your other Fabric operations."
For the implementer — measure it before you budget it

Copilot in Fabric consumption appears in the Fabric Capacity Metrics app in capacity units, filtered to the "Copilot in Fabric" operation, with a 30-day item-history breakdown. Microsoft processes it deliberately as a background operation to smooth demand rather than let it spike. Downstream work it triggers — DAX queries, refreshes, subscriptions — bills separately through the normal paths.

If you need isolation: a Fabric Copilot Capacity is billed only for Copilot consumption, with downstream operations still charged to the item's own capacity. It must be F2/P1 or higher, is supported only in the tenant's home region, allows one per user, and does not support Fabric AI functions. The heavier alternative Microsoft documents is a split-capacity strategy — Copilot alone on a separate F64-or-higher SKU.

05What is retained, and by which surface

Both vendors have surface-dependent retention, and summaries of both flatten it. The companion page covers Claude in detail; here is Copilot, then the comparison.

GitHub Copilot

  • The model-hosting layer runs under zero-retention agreements. OpenAI models are hosted by OpenAI and GitHub's Azure infrastructure with a zero data retention (ZDR) agreement in place. Microsoft's own models run on Azure in GitHub's tenant. Open-weight models are covered by zero-retention agreements with their hosting providers — one of which is a third party, Fireworks AI.
  • Copilot Chat messages are kept 28 days, then permanently deleted. On Business and Enterprise, memories can be viewed and deleted by an administrator.
  • No training on Business or Enterprise data. On individual plans — Free, Pro, Pro+, Max — GitHub may use prompts, suggestions and code snippets to train, with an opt-out.
The model picker is a retention control, and almost nobody treats it as one

Per GitHub's own documentation: when Claude Fable 5 or Fable 5.1 is used, "Anthropic retains data, including prompts and outputs, by default to operate safety classifiers that detect harmful use." A time-boxed zero-retention exemption is available through the end of 2026 while Anthropic rolls out Enterprise Frontier Safeguards; after that, continued use requires them. Eligibility runs through your GitHub account team, and an administrator must still enable each model individually.

Every other Claude model in Copilot stays under zero retention. So on Copilot, picking a frontier model from a dropdown can change your retention posture — quietly, and without touching a policy page.

06Where Copilot is genuinely better

Stated plainly, because a comparison written by a Claude Code user should be suspected of bias.

  • The Fabric-native notebook agent. Nothing on the Claude side knows what a default lakehouse is. Preview status notwithstanding, this is a real advantage for notebook work.
  • VFS mode and the remote Spark kernel. Editing workspace items in place and executing on remote compute, from the editor, with no sync dance.
  • Completions are unlimited and unbilled on every paid plan — the most-used feature costs nothing per use.
  • Pooled credits suit a small team. No per-person allowance to manage and no upgrade decision per head.
  • Admin-managed memory. Viewable and deletable by an administrator, which is a control Claude's local Cowork sessions lack.
  • Content exclusion. Administrators can define paths and repositories Copilot may not read as context — worth verifying against your own tenant rather than taking from a summary, including this one.
  • Model breadth with disclosed hosting. Claude, OpenAI, Microsoft and open-weight models behind one seat, and a public page saying where each one runs.
A claim I had wrong, and the correction matters

I initially said Copilot held an intellectual-property indemnity advantage. It does not. Anthropic's Commercial Terms §K.1 commit Anthropic to defend the customer and indemnify judgments on third-party claims that paid use of the Services "or Outputs generated through such authorized use violates any third-party intellectual property right." GitHub and Microsoft make a comparable commitment for Business and Enterprise.

Both vendors indemnify. Each attaches conditions — GitHub's is generally tied to keeping duplication filters enabled, Anthropic's to use being in accordance with the Terms. Read your own contract; do not take this from a comparison table. One detail for a European entity: Anthropic contracts through Anthropic Ireland, Limited for customers in the EEA, Switzerland and the UK, with venue in the courts of Ireland.

The honest summary

GitHub Copilot's governance story is good, and in places better than Claude's. Copilot in Fabric's is the weakest of the three surfaces on this page — not because Microsoft built it badly, but because it runs inside a shared capacity and may need to route data outside your compliance boundary in order to work at all.

08What I'd run — and the case against it

The recommendation

Run both, with roles.

GitHub Copilot in VS Code for notebook and in-editor work. The Fabric extension plus the Fabric-aware agent is the best notebook-authoring setup available to a Fabric team today, and Business at $19/user with pooled credits and free completions is good value for a dozen people.

Claude Code in the terminal for everything scripted, cross-repo, CLI-driven or unattended — including the fab route into Fabric from the companion page.

Copilot in Fabric: decide deliberately, and probably not yet. If you need the cross-geo setting enabled for it to work at all, that is a data-residency decision rather than a tooling one, and it belongs with whoever owns your compliance posture. If you do enable it, isolate the capacity first so it cannot throttle your pipelines.

Whichever you run, the rule from the companion page still holds and is not vendor-specific: don't point any of them at production data, and keep a named human in the audit log rather than a shared service principal.

The case against all of that

Steel-manning the opposite position

Running both is how tool sprawl gets justified. Two agent subscriptions is $39–120 per person per month for heavily overlapping capability, plus two sets of permissions, two audit trails, two vendors to track, and a team that has to remember which tool to reach for. "Use the right tool for the job" is the argument every organisation makes on the way to paying for five things that each do 80% of the same work. One tool used well usually beats two used casually.

And my Fabric caution may be miscalibrated. I am recommending against Copilot in Fabric largely on cross-geo processing — but if your capacity sits in a region where Azure OpenAI is natively available, that setting never comes up and the objection evaporates. I have not checked which regions those are for your tenant. Treat my caution as a question to answer, not a conclusion to adopt.

Where I land, and why. If forced to pick one for a twelve-person Fabric team, I would pick GitHub Copilot — not because it is the better agent, but because the Fabric-native integration, the free completions and the pooled credits fit that team's actual shape, and notebook work is the bulk of the job. I would expect to miss Claude Code's terminal within a month, which is exactly why the two-tool answer keeps winning on reflection.
